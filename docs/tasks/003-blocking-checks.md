# Задача 003: блокирующие проверки, git-хуки и CI

## Цель

`npm run check` сейчас только предупреждает и всегда завершается с кодом 0 — он ничего не защищает. Нужно превратить его в настоящий предохранитель: ошибки останавливают коммит, а не остаются заметкой в выводе.

Проверки, которые ломают код документации молча (битая ссылка, протухшая карта, потерянная задача, дыра в нумерации ADR, разошедшиеся формула и документ, ключ конфига без строки в документе, утёкший секрет), должны быть найдены машиной. То, что требует решения человека (длина файлов, размер карты, тон формулировок), остаётся предупреждением.

Хуки и CI нужны для одного: чтобы автор, вернувшись через месяц, не мог закоммитить состояние, которое уже рассыпалось.

## Шаги

1. **Разведка.** Прочитать `tools/check-docs.mjs`, запустить, составить карту: что уже есть, чего нет, что предлагать. Остановиться и дождаться утверждения.
2. **Проверки.** Реализовать недостающее по одной за раз: понятное сообщение на английском, ненулевой код выхода, тест на плохом и хорошем примере. Сначала исправить то, что проверка находит в репозитории, потом включать блокировку.
3. **Отчёт.** Свод: что включено, что нашло реальные ошибки, что исправлено, что пропущено и почему. Остановиться.
4. **Хуки.** `npm install` сам включает `core.hooksPath .githooks`; `pre-commit` — быстрые проверки, `pre-push` — typecheck, тесты, check. Показать, что плохой коммит реально блокируется.
5. **CI.** Workflow на push в `main` и на pull request: полная история, Node из проекта, `npm ci`, typecheck, test, check. Проверка «формула и документ меняются вместе» в CI смотрит на диапазон коммитов push.
6. **Финал.** Заполнить «Прогресс», переписать часть B `START-HERE.md`, `npm run map`, `npm run check`, push.

## Правила

- `docs/conventions.md` обязателен: один факт в одном месте, код и коммиты на английском, доки на русском.
- Ничего не обходить: `--no-verify` и `--force` в этой задаче запрещены.
- Число тестов нигде не записывать вручную.
- Задача 002 (индикатор приоритета) на паузе до завершения 003–004, её состояние не трогать.

## Открытые вопросы

1. **Тест, что при `NODE_ENV=production` боевая песочница не монтируется.** Автоматикой не делается: DEV-TOOL монтируется в `server/src/index.ts`, а не в текстах. Вернуться, когда появится сервер и арена.
2. Ссылки `raw.githubusercontent.com/.../main/...` в `docs/` остаются предупреждением проверки (h) — чистка вместе с картой проекта.

Отложено целиком (решение автора — вернуться после появления сервера и арены):

- **CI на GitHub.** Проверки готовы и работают локально, сам workflow удалён: на Linux падал `tsc` и `vitest` — в lock, созданном на Windows, лежат только win32-нативные пакеты (`@typescript/typescript-win32-x64`, `@rolldown/binding-win32-x64-msvc`, `@esbuild/win32-x64`). Пока нет арены, гонять CI незачем.
- **TypeScript.** Стоит 5.9.3 — версия 7 требует платформенный бинарник. Вернуться к 7, когда будет полноценный кросс-платформенный lock (генерация на Linux/WSL/CI).
- **Закрепление actions по хэшу коммита**, а не по мажорной метке `@v4`. Актуально, когда вернёмся к CI.
- Проверка «ADR не удалены и не перенумерованы» реализована (`tools/checks/adr-history.mjs`), но включается только через переменную `CHECK_BASE`, которую пока никто не задаёт — с появлением CI она включится сама.

## Итог

**Что сделано.** `npm run check` перестал быть предупреждениями и стал предохранителем. Прежние 7 проверок (длины, размер карты, дата части B, тон формулировок) остались предупреждениями — их нельзя чинить механически, они подсказывают. Добавлены блокирующие проверки: **(a)** битые относительные ссылки в `docs/**` и `START-HERE.md`; **(b)** протухшая карта `docs/INDEX.md` — сравнением с регенерированной в памяти, без переписывания рабочей копии; **(c)** задача из части B существует; **(d)** нумерация ADR без дыр и дублей, пропуск допустим только при строке «Зарезервированный ADR: NNN» в задаче; **(e)** `resolveAttack.ts` без `combat-formula.md` в том же коммите (локально — по staged, в CI — через `CHECK_RANGE`); **(f)** ключи из колонки «Ключ конфига» существуют в `config/*.json`; **(g)** секреты и приватные пути в `git ls-files`, значения не печатаются. **(h)** ссылки на `main` в `docs/` — предупреждение. Весь запуск обёрнут в try/catch: поломка самого скрипта даёт понятное сообщение и код 2, а не стектрейс.

Каждая проверка — отдельный модуль в `tools/checks/` с тестами на плохом и хорошем примере; тесты вошли в `npm test` и падают вместе с ним. Гейт стал автоматическим: `npm install` включает git-хуки, `pre-commit` гоняет `npm run check`, `pre-push` — `typecheck`, `test` и `check`.

**Что нашло реальные ошибки.** Проверка (b) трижды поймала протухшую карту — каждый раз, когда появлялись новые файлы в `tools/`. Кроме этого: два ложных срабатывания, найденных по ходу (ключи конфига в чужих колонках таблицы; секреты в самих тестах) — исправлены в логике проверок, а не ослаблением правил. Проверка нумерации ADR при большом разрыве выдавала 77 отдельных ошибок вместо одной — сгруппировано в диапазон.

**Что не сделано и почему.** CI отложен решением автора до появления сервера и арены; вместе с ним отложены выбор версии TypeScript и закрепление actions по хэшу. Не сделана проверка «песочница не монтируется в production» — см. «Открытые вопросы». ADR не создавалась: решения технические, архитектуру не меняют.

**Один факт — в одном месте.** Правила проверок живут в `tools/checks/`, пороги и тексты сообщений — там же, оркестрация — в `tools/check-docs.mjs`, список блокирующих — в этом файле.
