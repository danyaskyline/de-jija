# Handoff — передать контекст в новую сессию

Когда это нужно: автор говорит «лимит», «handoff» или «переходим в другой чат».

1. Остановить работу, новых правок не начинать.
2. Перезаписать ЧАСТЬ B в `START-HERE.md` целиком (не дописывать), максимум 30 строк: активная задача, цель, сделано, в процессе, следующий шаг, тронутые файлы, как проверить, тесты, подводные камни, открытые вопросы, дата и роль. Часть A не трогать.
3. Если добавлялись, удалялись или переименовывались файлы — выполнить `npm run map`.
4. Коммит с сообщением `wip: handoff — <кратко о чём>`.
5. `git push origin main` — без `--force` и `--force-with-lease`.
6. Если тесты красные — это допустимо для wip-коммита, но в части B указать, какие именно и почему.
7. Вывести автору готовое сообщение для новой сессии. Ссылка — обычным текстом, не markdown-ссылкой, и обязательно с **полным хэшем коммита**, а не с `main`:

```
Продолжаем работу над de-jija. Прочитай:
https://raw.githubusercontent.com/danyaskyline/de-jija/<полный_хэш>/START-HERE.md
Больше ничего не читай, пока не скажу. Кратко перескажи, где мы, и жди.
```

   Значение `<полный_хэш>` взять командой `git rev-parse HEAD` **после** коммита и push.

8. **Пометка:** если после handoff были новые коммиты, сообщение нужно сформировать заново — хэш в ссылке устареет, и новый чат прочитает не то состояние.
