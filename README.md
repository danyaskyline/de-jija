# de-jija

Браузерная/клиентская MMO в духе Heroesland и Heroes of Might and Magic III: пошаговые тактические бои на гексагональном поле, а карта приключений работает в реальном времени. Собственная графика, звук и названия — без ассетов HoMM3/Heroesland, но опытный игрок узнает первоисточник по ощущению боя.

Главные отличия от Heroesland: горизонтальная прогрессия вместо вертикального «жира», экономика, управляемая игроками, сила — в предметах-расходниках (калька Albion Online), а не в статах героя или в армии, и full loot при поражении в PvP-зонах (теряется только надетый шмот). Армия ничего не стоит и не теряется безвозвратно — она лишь временно слабее по кулдауну восстановления харизмы.

## Статус

Проект в разработке. Разрабатывается соло-автором в связке с ИИ-агентами: дизайн и архитектура фиксируются в `/docs`, реализация ведётся по этим документам.

Готов «walking skeleton»: клиент и сервер связываются по WebSocket (ping/pong) на выбранном стеке. Реализованы карта, размещение юнитов и бой с очередью ходов (группировка по скорости, начальный приоритет, переключение приоритета при равной скорости). Не сделано: БД, авторизация, поход и сам интерфейс боя в клиенте.

**Активная задача: [`002`](./docs/tasks/002-tie-rule-and-priority-indicator.md) — на паузе.** Сделано шагов 0–3 из 7; продолжить с шага 4 (индикатор приоритета). Раздел «Прогресс» в файле задачи — первое, что нужно прочитать, прежде чем браться за работу: в нём указано, что уже сделано, что осталось и какие особенности тестов не стоит переоткрывать. Правило рабочего цикла — в [`docs/conventions.md`](./docs/conventions.md).

## Структура репозитория

```
/server   — игровой сервер (Node.js + TypeScript, Express + ws)
/client   — клиент (TypeScript, PixiJS, сборка через Vite)
/shared   — общие типы протокола между сервером и клиентом
/docs     — документация проекта (источник правды по дизайну и архитектуре)
```

## Как запустить (нужно два терминала)

Нужен Node.js 20+ и npm (проверено на Node 24).

1. Установить зависимости — один раз, из корня репозитория:
```
npm install
```
2. Терминал 1 — сервер:
```
npm run dev:server
```
Ждём в консоли такую строку: `[http] listening on http://127.0.0.1:3000 (websocket: ws://127.0.0.1:3000)`
3. Терминал 2 — клиент:
```
npm run dev:client
```
Vite напечатает адрес: `http://localhost:5173/`
4. Открыть `http://localhost:5173/` в браузере и нажать **F12** → вкладка **Console**.

### Что означает «всё работает»

Чёрный экран в браузере — это нормально: сцена пока пустая, рисуется только пустой canvas PixiJS. Смотрим в консоль браузера:
```
[pixi] renderer ready, canvas 1920x1080
[ws] connected to ws://localhost:3000
[ws] pong received — latency ~1 ms (server time: 1790735413669)
[ws] pong received — latency ~1 ms (server time: 1790735415092)   <- затем каждые ~2 секунды
```
В консоли сервера:
```
[ws] client #1 connected from 127.0.0.1 (online: 1)
[ws] client #1 ping -> pong
[ws] client #1 disconnected (online: 0)      <- когда закроете вкладку браузера
```
Если строки `pong received` не появляются — почти наверняка не запущен сервер (в консоли браузера тогда будет `[ws] connection error`).

## Полезные команды

```
npm test               — юнит-тесты (vitest): сейчас это боевая логика resolveAttack
npm run typecheck      — проверка типов во всех пакетах (server, client, shared)
npm run build:client   — собрать клиент в client/dist
```
После `npm run build:client` сервер сам отдаёт собранный клиент — можно открыть `http://127.0.0.1:3000/` и запускать только один процесс (Vite в этом случае не нужен).

Баланс боя лежит в файле `config/combat-rules.json` (капы атаки/защиты, штраф морали, минимальный урон). Он читается один раз при старте сервера, поэтому после правки файла сервер нужно перезапустить.

Песочница боя — отладочный инструмент (не часть игры): запустите `npm run dev:server` и откройте `http://127.0.0.1:3000/debug/combat-sandbox`. Форма показывает каждый промежуточный шаг расчёта урона, итоговый урон и служебные заметки движка.

## Настройки через переменные окружения

- Сервер: `PORT` (по умолчанию 3000), `HOST` (по умолчанию `127.0.0.1`; поставьте `0.0.0.0`, чтобы зайти с телефона или другого устройства — тогда Windows может один раз спросить про доступ в сеть).
- Клиент: `VITE_WS_URL` в файле `client/.env` (по умолчанию `ws://localhost:3000`).
