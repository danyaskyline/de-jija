# Handoff между ИИ-агентами — как передавать контекст

Входная точка для нового чата: [START-HERE.md](https://github.com/danyaskyline/de-jija/blob/main/START-HERE.md).
Карта репозитория: [docs/INDEX.md](https://github.com/danyaskyline/de-jija/blob/main/docs/INDEX.md).
Правила проекта: [docs/conventions.md](https://github.com/danyaskyline/de-jija/blob/main/docs/conventions.md).

Ниже — триггеры, по которым агент обязан действовать описанным образом.

---

## Триггер 1. «лимит» / «handoff» / «переходим в другой чат»

Остановить работу (не начинать новых правок) и выполнить по порядку:

1. **Перезаписать ЧАСТЬ B в [START-HERE.md](https://github.com/danyaskyline/de-jija/blob/main/START-HERE.md)** целиком (не дописывать):
   активная задача (ссылка на файл в `docs/tasks/`), цель, сделано, в процессе, следующий шаг,
   тронутые файлы, как проверить (команды), состояние тестов, подводные камни, открытые вопросы,
   дата и модель. Максимум 30 строк. Часть A не трогать.
2. Запустить `npm run map`, **если менялась структура файлов** (добавлены/удалены/переименованы файлы).
3. Коммит: `wip: handoff — <кратко о чём>`.
4. Push в `origin/main` **без force**.
5. В конце вывести пользователю **готовое сообщение для нового чата** (см. шаблон ниже),
   в котором есть ссылка на [START-HERE.md](https://github.com/danyaskyline/de-jija/blob/main/START-HERE.md).

**Тесты.** Если тесты красные — это допустимо в wip-коммите. Но обязательно указать в части B:
какие именно тесты красные и почему они красные. Никогда не оставлять это без объяснения.

Шаблон сообщения для нового чата:

```
Продолжаем работу над de-jija. Прочитай START-HERE.md:
https://github.com/danyaskyline/de-jija/blob/main/START-HERE.md
Там состояние проекта и активная задача. Дальше читай только то, что реально нужно.
```

## Триггер 2. «продолжаем» / новая сессия

1. Прочитать **только** [START-HERE.md](https://github.com/danyaskyline/de-jija/blob/main/START-HERE.md).
2. Кратко пересказать состояние: активная задача, что сделано, следующий шаг, состояние тестов.
3. **Ждать команду пользователя.** Ничего не редактировать и не «доделывать» самовольно.

---

## Триггер 3. «запиши решения» (пользователь вставляет текст решений из веб-чата)

1. Добавить решение в [docs/decisions.md](https://github.com/danyaskyline/de-jija/blob/main/docs/decisions.md)
   в формате ADR этого файла (следующий свободный номер, тот же стиль разделов).
2. Если решение влияет на задачу — добавить его в раздел «Прогресс» активной задачи в `docs/tasks/`.
3. Обновить часть B в [START-HERE.md](https://github.com/danyaskyline/de-jija/blob/main/START-HERE.md).
4. Коммит: `docs: ...` (коротко о сути решения). Push в `origin/main` без force.

---

## Экономия лимита (обязательно во всех сессиях)

- **Не читать файл целиком, если нужна часть** — использовать диапазон строк или поиск по тексту (grep).
- **Не перечитывать** то, что уже прочитано в этой сессии.
- **Перед чтением более 5 файлов** — коротко написать пользователю, зачем они нужны.
- **Не исследовать код «на всякий случай».** Контекст задаётся документацией и разделом «Прогресс» задачи.
- **Не открывать `package-lock.json`** (и вообще игнорировать его, `.clineignore`).

## Регулярное обслуживание

- После **добавления или удаления файлов** — запустить `npm run map` (обновляет [docs/INDEX.md](https://github.com/danyaskyline/de-jija/blob/main/docs/INDEX.md)).
- После **каждого значимого шага** — коротко обновлять раздел «Прогресс» в файле задачи
  (максимум 15 строк; закрытые/завершённые пункты сворачивать в одну строку).
